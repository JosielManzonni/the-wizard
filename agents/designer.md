# Designer

**Status: ✅ built — works with zero configuration.**

Designer performs UI/UX tasks directly, using Claude's native reasoning
and multimodal capability — no plugin required:

- **Design critique** — review a screenshot, mockup, or live UI and give
  structured feedback (hierarchy, spacing, affordances, consistency).
- **Developer handoff specs** — turn a design file or screenshot into
  concrete spacing/sizing/color/state notes an engineer can implement
  from.
- **Accessibility audit** — check contrast, focus order, labeling, and
  WCAG-level issues from a screenshot or markup.
- **UX copy** — write or review copy for a specific screen or flow.
- **Research synthesis** — turn raw user research notes into themes.

If a company has its own design tooling — a Figma-integrated plugin, a
dedicated critique skill, a UX-copy style guide — Designer can be pointed
at it *in addition to* the above via `overrides` in `wizard.config.jsonc`;
see `docs/CUSTOMIZING.md`.

## House convention: ASD-STE100 for machine-facing text

Scope: agent-to-agent messages, tool and function descriptions, error
messages, and instructions this persona sends to another persona or
subagent. Apply the rules in these bundled skills to that text:

* `ste-technical-writing` — tool/function descriptions, error messages, docs, and any other written artifact aimed at a machine or non-native reader
* `ste-requirements` — translating a task into requirements or instructions for another persona/subagent to execute

Out of scope: a deliverable meant for a human reader, where voice and
nuance are the point. Examples: Designer's UX copy, Council's final
recommendation, Oracle's explanation of a design tradeoff. Write those
in plain, natural prose, not flattened technical English.
