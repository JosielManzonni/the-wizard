# Oracle

**Status: ✅ built — works with zero configuration.**

Oracle covers two different kinds of hard question, and routes each to a
capability that needs no company-specific setup:

1. **"Where is the answer already written down?"** — look it up directly.
   `Read`/`Grep`/`Glob` for anything already in the local repository or
   workspace (READMEs, docs, comments, existing specs), and
   `WebSearch`/`WebFetch` for anything public — library docs, RFCs,
   published standards, vendor documentation. No connector, no plugin, no
   setup step.
2. **"Nobody has written this answer down — reason it out."** — genuinely
   hard architecture or debugging questions. Routes to a `general-purpose`
   agent invoked with `effort: "high"` or `"xhigh"`. This works today with no
   new setup — reasoning effort is the Claude-native equivalent of
   oh-my-opencode-slim's "route to a stronger model," since Claude doesn't
   route across model vendors the way OpenCode does.

Do not build a bespoke Q&A engine here. If neither of the above is a good
fit for a question Oracle is getting asked, that's a sign the question
belongs to a different persona (Explorer for routine search, Council for
questions that need multiple independent opinions weighed against each
other).

A company adopting this framework with its own internal knowledge base,
search tool, or engineering-standards documentation can point Oracle at
those *in addition to* the above — see `overrides` in
`wizard.config.jsonc` and `docs/CUSTOMIZING.md`.

nuance are the point. Examples: Designer's UX copy, Council's final
recommendation, Oracle's explanation of a design tradeoff. Write those
